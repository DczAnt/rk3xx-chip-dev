# RK3588 芯片能力描述

> SoC: RK3588 | 架构: aarch64 (ARMv8, big.LITTLE: A76×4 @2.4GHz + A55×4 @1.8GHz)
> RK3XX 系列旗舰，NPU 三核，VPU/RGA 双实例。

## 硬件加速器

| 模块 | 能力 |
|------|------|
| rkvdec ×2 | **双核**硬解 H.264/H.265/VP9/AV1 |
| rkvenc ×2 | **双核**硬编 H.264/H.265 |
| jpege / jpegd | JPEG 硬编/硬解 |
| RGA3 ×2 + RGA2 ×1 | **三实例** 2D 加速（RGA3 性能更强） |
| NPU ×3 | **三核** 6 TOPS INT8，RKNPU v1.0+ |
| VOP2 | 4 路 HDMI/MIPI/DP 输出 |

## NPU 能力（关键差异点）

- **核心数**: 3（三核）
- **core_mask 有效值**: `NPU_CORE_AUTO`(0) / `NPU_CORE_0`(1) / `NPU_CORE_1`(2) / `NPU_CORE_2`(4) / `NPU_CORE_0_1`(3) / `NPU_CORE_0_1_2`(7) / `NPU_CORE_ALL`(0xffff)
- **三核并行**: 创建 3 个独立 context 分别绑 `CORE_0`/`CORE_1`/`CORE_2`，配合 3 个推理线程
- **量化类型**: INT8
- **rknnrt 版本**: 2.3.x（需匹配板子驱动版本）

## RGA 能力

- **实例数**: 3（RGA3 ×2 + RGA2 ×1）
- **RGA3 vs RGA2**: RGA3 性能更强，支持更多格式，API 类似但 `im_opt_t.core` 枚举值不同
- **双实例调度**: `im_opt_t.core` 指定 scheduler

## VPU JPEG

- **可用**: `mjpeg_rkmpp` 编码器
- **输入格式**: `AV_PIX_FMT_NV12`（与 RK3576 相同限制，不接受 DRM_PRIME）

## CPU big.LITTLE 绑核

| 核心范围 | 架构 | 频率 | 适合 |
|---------|------|------|------|
| CPU0-3 | Cortex-A55 | 408-1800 MHz | I/O 密集 |
| CPU4-7 | Cortex-A76 | 408-2400 MHz | 计算密集 |

## SDK 路径（板上）

| 组件 | 路径 |
|------|------|
| MPP 头文件 | `/usr/include/rockchip/` |
| RKNN 头文件 | `/usr/include/rknn_api.h` 或 `/usr/include/rknn/rknn_api.h` |
| RGA 头文件 | `/usr/include/rga/` |
| librknnrt.so | `/usr/lib/` 或 `/usr/lib/aarch64-linux-gnu/` |

**路径探测**: RK3588 不同发行版路径差异较大，建议用 `find / -name "librknnrt.so" 2>/dev/null` 探测。

## 典型 OS / glibc

- Ubuntu 22.04 / Debian 12 / glibc 2.35-2.36 / 内核 6.1.x
- **交叉编译**: 容器与板子 glibc 一致，直接动态链接

## 编译方式

- **板上原生编译**: gcc 12+，可行
- **Docker 交叉编译**: 推荐，aarch64-linux-gnu-gcc 12
